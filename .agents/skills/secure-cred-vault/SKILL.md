# Secure Credential Vault

**Complete process (install → end):** [README.md](./README.md)  
**Mandatory agent rules:** [AGENTS.md](./AGENTS.md)  
**Vault folder guide:** `/mnt/NewVolume/Personal_Projects/cred/HOW_TO_USE.md`

## What it is

One **passphrase-encrypted** file that decrypts to **category-organized plain JSON**.
Organize **by project** (the category is the product/app), so one machine can hold
many projects that happen to share a domain without mixing their secrets:

```json
{
  "cursor":  { "cloudflare_api_token": "…", "cloudflare_account_id": "…", "github_token": "…" },
  "atlas":   { "cloudflare_api_token": "…" },
  "openai":  { "api_key": "…" }
}
```

Path: `/mnt/NewVolume/Personal_Projects/cred/credentials.json.gpg`  
Backend: GnuPG AES-256 + jq via `scripts/cred-store.sh` (`cred` after install).

## Reset / recovery ("PIN") system

`init` generates a **recovery key** saved to `.recovery.key` (0600) and keeps a
mirror `credentials.recovery.gpg`. If the passphrase is forgotten:

```bash
cred reset-pass        # decrypts the mirror with the recovery key, sets a new passphrase (no data loss)
cred recovery-show     # print the recovery key
cred recovery-init     # (re)generate the recovery key for an existing vault
cred reset --wipe      # destructive: erase vault + recovery, start fresh
```

**Automation:** `CRED_PASSPHRASE`, `CRED_RECOVERY_KEY`, and `CRED_VALUE` (for `set`)
let agents run non-interactively on a trusted machine. Prefer hidden tty prompts
otherwise.

## Golden rules (all AI agents)

1. **Never save a secret pasted in chat.** Tell user to rotate, then `cred set` themselves.
2. **Never print decrypted values** into the conversation. `cred list` = names only.
3. **Never put secrets in argv** or store the vault passphrase.
4. **Wire projects by name:** `export X="$(cred get category key)"`.
5. Prefer **scoped API tokens** over Cloudflare Global API Keys.

## Store / use

```bash
cred set <category> <key>          # user types value
cred list
cred get <category> <key>
eval "$(cred env <category>)"
```

## If user pasted a secret in chat

1. Say it is exposed → rotate at provider.  
2. Do not write the pasted value anywhere.  
3. Have them `cred set <cat> <key>` with the new value.

## Categories — organize by project

Use the **project/product name** as the category and prefix provider keys, e.g.
`cursor/cloudflare_api_token`, `cursor/github_token`. This keeps multiple apps
that share infrastructure (e.g. several projects under one domain) cleanly
separated. Shared, non-project secrets can still use provider categories
(`openai`, `stripe`).

Example (this machine): `cursor` = the Cursor Curse Monitor software.

## Always-store rule

Whenever a new credential appears — provided by the user, generated by you, or by
any AI — store it in the vault under the right project category (`cred set
<project> <provider>_<key>`) and reference it by name afterward. Never leave keys
loose in `.env`, chat, or code.
